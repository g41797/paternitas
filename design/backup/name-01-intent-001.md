## The names

A Link is the std Node with a type check added. The name says so.

| old | new |
|---|---|
| `Link(N)` | `TypedNode(N)` |
| `SLink` | `SinglyTypedNode`, alias `STNode` |
| `DLink` | `DoublyTypedNode`, alias `DTNode` |
| `findLink` | `findTypedNode` |
| `stamp` | `setTypeId` |
| "its Link", in prose | "its TypedNode" |
| the struct field `link:` | `tnode:`, so `message.tnode.node` |

- Singly and Doubly, as in std. `std.DoubleLinkedList` does not exist.
- `findTypedNode` is camelCase. Only a function that returns a type is
  capitalised.
- `setTypeId` names the value it writes. It pairs with `typeId()`, which
  reads it. `setType` reads as "change the type". `stamp` needed an
  explanation.
- One word in code and in prose. "link" stays only for what std does: "the
  list links the Nodes".
- `tnode` avoids `node.node`.
- Old text uses "SNode" and "DNode" for the std Node. It becomes "the std
  singly Node" and "the std doubly Node", so it does not clash with
  `STNode` and `DTNode`.
- No old names are kept as deprecated aliases. Nothing is released yet.
